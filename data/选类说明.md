# 本组选类说明（50 个车型 + unknown）

> 数据来源：教师提供的 827 个车型类别。本组自选恰好 50 类，另加第 51 类 `unknown`。
> 类别 ID 与名称取自 `cls_info/class_info.json` 的 `id` 与 `name_from_new` 字段。

## 一、选类原则

1. **样本充足**：候选类别训练图 ≥ 85 张、验证图 ≥ 30 张，保证 Macro-F1 的每类统计稳定（全库中位数：train 97 / val 32）。
2. **品牌不重复**：50 个类别分属 50 个不同品牌，避免同品牌孪生车型互相干扰。
3. **外观差异大**：优先选取造型辨识度高的车型（方盒子越野、溜背轿跑、圆润复古、超跑楔形等），降低类间混淆。
4. **覆盖 7 种车身类型**：以 SUV 与轿车为主，兼顾跑车、MPV、皮卡、微面、轻客，便于后续做「同类车型对比」等业务功能。
5. **模型级粒度**：全部为具体车型，不使用品牌或「轿车 / SUV」等大类替代。

## 四、目录结构

```
data/
├── classes.txt           # 恰好 50 行四位 ID，升序，UTF-8 无 BOM，不含 unknown
├── class_mapping.json    # 索引 0~49 → 50 个车型，索引 50 → unknown（训练/推理/Web 共用）
├── build_dataset.py      # 数据集构建脚本，可重复运行
├── train/                # 51 个类别目录
│   ├── 0009/ ... 0984/   # 50 个目标车型
│   └── unknown/          # 120 张组外样本
└── val/                  # 同结构
    ├── 0009/ ... 0984/
    └── unknown/          # 48 张组外样本
```

合计 train 5812 张、val 1931 张。文件均为指向原始 `train/`、`val/` 的**硬链接**，不额外占用磁盘空间。

## 五、提交前提醒

- `classes.txt` 最终必须放在**项目根目录**，且与教师登记的版本一致。
- 模型索引必须严格按 `classes.txt` 的行顺序，第 51 个索引输出字符串 `unknown`，不输出其来源车型 ID。
- 后续若更换类别，直接修改 `build_dataset.py` 中的 `SELECTED` 后重跑，并清理 `data/train`、`data/val` 旧目录。
